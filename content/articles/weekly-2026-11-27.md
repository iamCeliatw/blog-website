這週讀完一輪文章，反覆出現的關鍵字是「失控」跟「邊界」。不管是 AI 代理、串接介面還是雲端主機，工具一多，沒先畫好規則就容易出事。

## MCP 變成新入口，防護也得跟上

把 MCP 想成開給 AI 的側門。以前大家忙著開門讓代理進來做事，現在門開多了，門禁也開始被盯上。

- **大廠強制走統一介面**：[Google 宣布從 2027 年 2 月起](https://daily.dev/posts/google-requires-ai-agents-to-use-workspace-mcp-servers-and-a-cli-instead-of-rest-apis-from-february--7oxqjc2cy)，要求 AI 代理改用 Workspace MCP 伺服器與 CLI，不再直接用 REST API，免費版每日限五千次，主打安全串接。
- **攻擊已經對準開發工具**：[Infrawatch 的調查](https://www.itsecurityguru.org/2026/11/24/autonomous-ai-attack-tools-target-coding-agents-chatbots-and-retail-payment-systems-infrawatch-finds)指出，駭客用自主 AI 攻擊工具鎖定開發助手、聊天機器人、零售付款系統與 MCP，串接 AI 工具時驗證不能隨便做。
- **雲端防火牆補上這一塊**：[AWS WAF 推出新功能](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection)，透過 Amazon Bedrock Guardrails 自動探索並防護 LLM、MCP 與 A2A 端點，幫上雲部署的 AI 防範注入攻擊。

對正在準備 AWS SAA 的我來說，看到 WAF 防護範圍延伸到 MCP 端點，是一個很明確的訊號：AI 元件上雲後，一樣要照安全架構的標準做法納管。

## 多開 AI 寫程式，重點從加速變成控管

很多人以為同時開好幾個 AI 代理就能倍速開發，結果反而像把幾個人塞進同一間廚房，沒分工只會互相撞倒。

- **放任寫程式的代價**：[這篇開發者心得](https://daily.dev/posts/how-ai-coding-agents-ended-up-making-me-a-slower-developer-tat9lzizv)提到，放任 AI 寫程式反而讓部署被拖到 90 分鐘，最後得靠 Hooks 與變異測試止血。
- **隔離執行環境**：[Fleet](https://daily.dev/posts/fleet-parallel-branch-sessions-ov7g6xzap) 這個 VS Code 套件會替 AI 分配獨立分支與埠號，多開 Claude 不會互搶；[Agent Tree 0.7.19](https://daily.dev/posts/agent-tree-0-7-19-your-claude-code-agents-across-terminals-with-a-local-model-g8xsl1nzr) 則是免費工具，能跨終端機監控多開的 Claude Code 防撞檔，還可以把簡單任務分流給本機模型。
- **減少餵給 AI 的雜訊**：[T-Zero](https://daily.dev/posts/t-zero-local-rust-python-ast-context-compressor-mcp-server-94-5-fewer-repo-tokens--bfxdwivvg) 透過本機 MCP 工具轉出 AST 骨架，省下 94.5% 的專案 Token，讓 AI 更快掌握大型專案。

這些工具都在處理同一件事：別把整個專案無腦丟給 AI，先把分支、檢查機制跟輸入範圍切乾淨。

## 雲端環境一直變，靠人工對齊一定失真

雲端主機跟設定不會停在畫完架構圖的那一天。只要有人手動改過設定，架構圖跟線上狀態就開始分家。

- **校對線上狀態**：[這篇架構討論](https://daily.dev/posts/your-architecture-diagram-says-one-thing-production-says-another--mom1smmqo)點出手動改 AWS 設定會讓架構圖失真，解法是用 Terraform 校對線上狀態。
- **動態管理主機清單**：[Ansible Dynamic Inventory 的介紹](https://daily.dev/posts/devops-concepts-19-25---ansible-dynamic-inventory-managing-changing-infrastructure-automatically-swq1zkcm1)則是依 AWS 標籤動態分群 EC2，取代手動清單來因應主機變動。
- **保留真實來源**：[AWS Global Accelerator 更新](https://aws.amazon.com/about-aws/whats-new/2026/11/global-accelerator-client-ip-nlb-tls)讓開啟 TLS 監聽器的 NLB 也能保留用戶端真實 IP，讓 AWS 限流與防護更精準。

三件事合起來看，核心都是「讓系統直接反映真實狀態」，少一點人工記憶跟假設。
